# 1. 项目概述

## 1.1 项目背景

Star GYM 是一个面向中小型健身房的数字化综合管理平台。当前健身房行业存在会员管理混乱、课程预约效率低、教练资源闲置、运营数据缺失等痛点。

本项目旨在通过一套完整的：

* 移动端 Flutter App
* Vue 3 Web 管理后台
* Spring Boot 后端服务

帮助健身房实现：

* **会员体验升级**：扫码入场、在线购卡、课程预约、运动数据记录。
* **运营效率提升**：自动化会员管理、教练入驻审核、通知推送。
* **数据驱动决策**：运营数据看板、多维度统计报表。

---

## 1.2 项目目标

### 业务目标

| 目标               | 衡量指标               |
| :--------------- | :----------------- |
| 会员自助服务率 ≥ 80%    | 购卡、预约、退卡在线完成比例     |
| 教练入驻审核周期 ≤ 24 小时 | 从提交申请到审核完成的平均时长    |
| 运营数据可视化          | 看板覆盖 5+ 核心指标       |
| 系统可用性 ≥ 99.5%    | 月度服务不可用时间 < 3.6 小时 |

### 技术目标

* **前后端分离**：Flutter + Vue 3 + Spring Boot。
* **高可扩展性**：支持未来多场馆、多租户扩展。
* **安全合规**：JWT 鉴权、密码加密、操作审计日志。
* **容器化部署**：支持 Docker + Docker Compose 一键启动。
* **Web 管理后台**：管理员端针对 PC/桌面浏览器进行适配。

## 2.1.2 统一响应格式

所有 API 返回统一格式：

```json

  "msg": "success",
  "data": {}
```

* `code = 0`：成功
* `code > 0`：业务错误
* `code < 0`：系统错误

全局异常处理覆盖：

* 参数校验失败
* 资源不存在
* 权限不足
* 业务规则冲突
* 系统异常

# 2.2.4.8 月度运动统计

### 统计依据

月度运动统计**只根据 `exercise_records.exercise_date` 进行统计。**

不使用：

* `gym_visits.entered_at`
* `gym_visits.exited_at`
* 扫码入场时间
* 扫码出场时间

### 统计规则

同一个用户：

```text
2026-08-16
跑步机 30 分钟

2026-08-20
力量训练 40 分钟
```

则：

```text
运动天数 = 2 天
累计运动时长 = 70 分钟

运动日期：
2026-08-16
2026-08-20
```

如果同一天存在多条运动记录：

```text
2026-08-16
跑步机 30 分钟

2026-08-16
力量训练 40 分钟

2026-08-16
椭圆机 20 分钟
```

则：

```text
运动天数 = 1 天
累计运动时长 = 90 分钟
```

### SQL 逻辑

```sql
SELECT COUNT(DISTINCT exercise_date)
FROM exercise_records
WHERE user_id = ?
  AND exercise_date >= ?
  AND exercise_date < ?;
```

累计时长：

```sql
SELECT COALESCE(SUM(duration_minutes), 0)
FROM exercise_records
WHERE user_id = ?
  AND exercise_date >= ?
  AND exercise_date < ?;
```

### 月度统计展示

* 当月运动天数
* 当月累计运动时长
* 运动日期列表
* 运动日历
* 有运动记录的日期高亮

## 5.2.1 exercise_date 的重要定义

`exercise_date` 表示：

> **用户实际进行并记录该次训练的日期。**

它不是：

* 记录创建时间
* 扫码入场时间
* 扫码出场时间

例如：

```text
用户今天 2026-08-20 创建了一条记录，
但选择运动日期为 2026-08-16。
```

那么这条记录属于：

```text
2026-08-16
```

统计时必须按照：

```text
exercise_date
```

计算。

# 9.4 V2.0 核心业务规则总结

为了避免开发时理解错误，V2.0 最核心的规则统一如下：

### ① 运动记录

```text
运动记录 = 用户手动添加
```

不是扫码产生。

---

### ② 力量训练

```text
部位：肩 / 胸 / 腹 / 背 / 臀 / 腿 / 手臂 / 核心
      ↓
支持多选
      ↓
动作名称
重量
组数
时间
日期
```

---

### ③ 椭圆机

```text
固定把手 / 摇摆把手
        ↓
      单选
        ↓
阻力
时间
日期
```

---

### ④ 爬楼机

```text
不提供选项
   ↓
速度
时间
日期
```

---

### ⑤ 跑步机

```text
不提供选项
   ↓
速度
坡度
时间
日期
```

---

### ⑥ 二维码

```text
二维码
  ↓
只能用于
  ↓
扫码进入 / 扫码离开
```

**不能用于：**

```text
❌ 自动创建运动记录
❌ 自动计算运动天数
❌ 自动计算运动时长
❌ 课程签到
❌ 训练记录
```

---

### ⑦ 月度运动天数

唯一统计依据：

```text
exercise_records.exercise_date
```

例如：

```text
08-16 跑步机
08-20 力量训练
```

结果：

```text
运动天数 = 2
```

如果：

```text
08-16 跑步机
08-16 力量训练
08-16 椭圆机
```

结果：

```text
运动天数 = 1
```

---

### ⑧ 到店数据和运动数据完全分开

```text
gym_visits
    ↓
扫码进出场
    ↓
到店/在馆数据
```

```text
exercise_records
    ↓
用户手动记录
    ↓
运动数据
```

二者不能混用。

---

### ⑨ 所有日期必须可点选

原则：

> **凡是需要用户/管理员填写日期的地方，都不能要求手动输入日期，必须提供日历选择器。**

包括：

```text
运动记录日期
运动记录月份筛选
课程时间
教练空闲时间
管理后台统计年月
其他日期/时间字段
```
